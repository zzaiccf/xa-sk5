0.1.17 工程預覽版 · Windows 11 x64 · 繁體中文

已完成普通 Windows 程序的實際轉送測試。 TCP／UDP 實際 IP 與代理一致，DNS 轉送通過。雷電、雙實例與兩小時驗收須分別記錄；「代理測試通過」仍不能代替每個窗口的出口驗證。套件不包含 WinDivert 驅動。

0.1.9 新功能：全局與子程序代理

  1. 「窗口管理 → 全局代理…」選一條節點，預設保留 IPv4 區網直連。按啟用後會先檢測；畫面明確顯示代理執行中或封鎖原因。全局涵蓋本機程序與背景服務的 IPv4 TCP／UDP，不限十個程序；可隨時按「停用全局」。
  2. 指定綁定、遊戲組、啟動保護與暫停封鎖優先。停用全局不解除指定綁定；全局開啟時解除綁定會改依全局規則連線。
  3. 「分配代理」或「自動代理」的一般程序規則可勾選「涵蓋子程序」。適用遊戲登入器及由主機網路程序連線的不同模擬器。應選實際負責連網的程序或可驗證祖先；獨立系統服務不是登入器的子程序時，可嘗試全局模式。
  4. 已觀察的子程序身分會保存，根程序結束或服務重啟仍保留原 IP；最後一個成員退出後才釋放名額。每棵樹上限 512 個子程序，父子同時分配到重疊綁定會封鎖。

127.0.0.0/8 與 ::1 的本機控制／ADB 通訊保留直連，DNS 53 埠例外，仍經代理送往 1.1.1.1。區網直連包含 IPv4 私有位址、link-local、多播與廣播；可取消勾選。外部 IPv6 不轉送。啟用後既有程式需要重新連線。

全局節點的上游主機先解析為 IPv4 並保存，避免代理解析自身形成循環；主機 IP 變更請重新套用。STUN 健康檢測由代理解析網域名稱，上游須支援 SOCKS5 UDP 網域封裝。代理服務本身的 SOCKS 上游及檢測連線不會再次被攔截。

本次完成原生政策、協議及服務回歸測試；全局實機封包及不同品牌模擬器尚待逐一驗收。不涵蓋橋接網卡、Hyper-V／WSL 轉送流量、ICMP 或所有反作弊遊戲。沒有 WFP 持久封鎖，服務／驅動停止或崩潰不保證阻止直連。

0.1.17：開機啟動

「設定 → 啟動設定 → 開機啟動 xa sk5」預設勾選：目前使用者登入 Windows 時開啟主程式，背景代理服務於開機時自動啟動。取消會同時移除主程式的登入啟動項目，將背景服務改為手動啟動，目前的代理連線持續執行。變更服務設定須親自核准 Windows 管理員授權，取消或失敗時保留原設定。

取消偏好會保存，升級及新版修復安裝不會重設。需要時手動開啟主程式，在設定按「啟動背景服務」即可使用；這不會重新開啟自動啟動。可攜資料夾移動後請手動開啟一次以更新啟動位置。重複開啟會回到現有視窗。

捷徑、更新與批次匯入

首次開啟會建立桌面與開始功能表捷徑；自行刪除的桌面捷徑不會在每次啟動或升級後重建，可在「設定 → 捷徑與工作列」補建。「釘選工作列」由 Windows 顯示確認；不支援的版本請在工作列圖示按右鍵選擇「釘選到工作列」。

按「設定 → 檢查更新」會立即查詢最新發布，不需再按一次；視窗內可按「重新檢查」。批次匯入會先顯示已儲存節點與到期日，整批立即標示「檢測中」，最多 5 條並行先測 TCP，取得實際 IP 與延遲立即顯示；UDP 與所在地另在背景補測，不阻塞 TCP 佇列。UDP 尚未完成會標示待測，完整通過後才計入 TCP／UDP 可用數。定期模擬器探索與慢速檢測不會阻塞匯入。

1. 開啟與安裝

  1. 先執行可攜資料夾中的 xa sk5.exe。所有 DLL 必須保留在同一資料夾，不要只複製 EXE。
  2. 需要常駐背景服務時，執行 xa-sk5-Setup-0.1.9.exe，自行在 Windows 權限提示中核准。請使用之後要操作 xa sk5 的同一個 Windows 帳戶安裝。
  3. 安裝位置為 C:\Program Files\WindowSocks。安裝器建立背景服務、開始功能表捷徑、解除安裝項目，以及只針對服務程式的 TCP／UDP 輸入防火牆規則。
  4. 若已在可攜模式匯入代理，安裝後到「設定 → 移交離線設定」。

程式與安裝包目前未做商業程式碼簽章。驅動不是內建 .NET 執行階段的一部分；沒有驅動時，服務也不會假裝已啟用代理。

直接從程式安裝驅動與服務

  1. 開啟「設定 → 安裝／修復」。先關閉受管遊戲／模擬器，因為修復會重新啟動服務。
  2. 確認操作後，在 Windows 管理員授權（UAC）視窗親自按「是」；一般帳戶可能需要輸入管理員帳密。程式不會自動按下同意。
  3. 維護視窗會檢查程式套件、準備安裝位置、從官方 GitHub 下載 WinDivert 2.2.2，驗證 x64 與驅動數位簽章，再建立背景服務並測試驅動載入。
  4. 看到「服務已啟動、驅動可載入」後按「關閉並返回 xa sk5」。離線代理會在服務連線成功後移交。接著仍需綁定實例與驗證實例出口。

可攜版會自動將程式安裝到標準目錄，無須手動搬 DLL。若安全軟體阻擋下載、簽章驗證或載入，會顯示具體失敗原因；UAC 授權不等於解除防毒攔截。安裝紀錄為 %PROGRAMDATA%\WindowSocks\component-install.log。本次開發僅完成流程與非提升測試，沒有代替使用者同意 UAC 或聲稱已成功載入驅動。

0.1.14：RustDesk 與 RDxaomao 分支直連

勾選「全局代理 → 遠端控制程式直連」，會讓 RustDesk、RDxaomao.exe、RDxaomaoHost.exe、RDxaomaoControl.exe 的 TCP／UDP 直接使用原網路，包含無視窗背景程序。檔名不分大小寫，新增的 RDxaomao 系列需要 0.1.14 背景服務。其他編譯或改名版本可在「其他遠端程式」加入完整 .exe 路徑；指定代理、暫停封鎖與啟動保護仍優先。

0.1.13：模擬器可依順序或固定編號

到「自動代理 → 模擬器 → 分配方式」選擇：

  • 依啟動順序：選雷電或 MuMu 的管理程式，填每個 IP 的窗口數，儲存後依已辨識的虛擬機程序建立時間分配；編號不影響順序，既有窗口保持原 IP。關閉後釋放名額，重開重新排入。一個 IP 可共用 1–10 個窗口，總計最多十個；容量不足的匹配窗口保持封鎖。
  • 固定窗口編號：在表格指定窗口與節點，未啟動也保留，重開沿用；多個窗口可選同一節點。

依順序模式需要 0.1.13 背景服務；舊服務或離線時先保存草稿。MuMu 首次辨識新窗口請保持介面開啟或按「讀取窗口」，後續依已核實的 NAT 程序辨識；橋接模式與 MuMu 實際轉送仍需驗收。切換模式時既有可沿用的分配不換 IP，其他自動範圍保持暫停；不會因更新程式自行切換規則。

0.1.12：立即檢測與低頻複測

代理頁的「立即檢測」有選取時只更新選取節點，未選取時更新全部；右上角重新整理也會依選取範圍啟動新檢測。「更多 → 檢測全部節點」可直接更新全部。開啟與匯入仍先檢測一次，成功後每 30 分鐘複測、失敗後 5 分鐘重試。暫停後仍可手動檢測，但須在「更多」明確恢復自動排程。背景服務的健康檢查採相同頻率，需要 0.1.12 服務；健康有效期調整為 37 分鐘以涵蓋排程與一次失敗後重試，首次未成功或連續兩次失敗仍封鎖。

0.1.11：全局代理保留遠端直連

開啟「全局代理」後，「遠端控制程式直連」預設勾選，讓 AnyDesk、Chrome 遠端、DeskIn、RdViewer、TeamViewer、RustDesk、RDP 等程序直接連線，減少代理繞路。未內建或改名的版本可展開「其他遠端程式」，加入完整 .exe 路徑；加入後該程式的全部連線直連。取消勾選並套用即可恢復全局代理。

指定窗口代理、子程序規則及暫停封鎖仍優先；共用 DNS 維持原有代理政策。RDP 服務端依實際監聽埠與程序身分辨識，不放行整個系統服務或通用埠。需要 0.1.11 背景服務與核心，舊元件會明確提示更新。尚未量測真實遠端延遲。

0.1.10：窗口計時與固定模擬器配置

窗口管理的「連入時長」是本次代理啟用時長，每秒更新；暫停、封鎖、換 IP、重開窗口或重啟服務後重新計時。將滑鼠移至時長，可查看開始時間及 TCP／UDP 連線數。尚未代理或舊服務沒有計時資料時顯示「—」。

  1. 開啟「自動代理」，目標類型選「模擬器」，選擇雷電或「其他模擬器 · MuMu」。
  2. 選擇 ldconsole.exe／dnconsole.exe 或 MuMuManager.exe，按「讀取窗口」。也可輸入模擬器原始編號（包含 0）按「加入編號」。
  3. 在每一列選擇固定代理；多個窗口可選同一節點。按「依編號配置」可依模擬器、安裝位置、編號順序快速填入，數量設定只影響快速配置，之後仍可手動調整。
  4. 按「儲存配置」。固定對應以模擬器種類、安裝位置與實例編號保存，尚未啟動的窗口也保留位置，啟動順序不影響指定的 IP。總管理上限仍為十個。

固定配置與服務端計時需要 0.1.10 背景服務。舊服務或離線時只儲存本機草稿，更新後須再次儲存套用。MuMu 使用官方 info 清單的 headless_pid 辨識 NAT 網路程序；首次啟動請保持介面開啟並讀取清單。背景服務以已核實的程序路徑及命令雜湊辨識重開，遇到變更或重複則等待重新讀取，不按開啟順序猜測。橋接模式與 MuMu 實機轉送仍需驗收。

手動軟體更新（0.1.15）

在「設定 → 檢查更新」按「檢查最新版本」，查看目前／發布版本、發布時間、下載大小與更新內容。確認後按「升級」才會下載，下載與準備可取消；下載會核對大小、SHA-256、檔案清單及主要元件版本。沒有背景版本檢查或自動升級。

更新程式會先備份，再關閉／重新開啟介面。若勾選一併更新已安裝背景服務，由使用者核准 Windows UAC，代理連線會中斷，遊戲可能需要自行重新連線；程式不會結束遊戲、模擬器或遠控。代理帳密、到期日、固定／順序配置、自動／全局及遠控例外均保留。失敗時回復原程式；中斷後可展開「更新來源與離線更新 → 回復上次更新」。備份位置與結果顯示在更新視窗。

離線使用時將發布的 latest.json 與 ZIP 放在一起，按「從檔案檢查」。只使用可信任的發布來源；SHA-256 驗證傳輸完整性，未提供 xa sk5 發布者的程式碼簽章。

2. 匯入與檢測代理

到「代理與檢測 → 匯入節點」，每行一組。以下內容只是格式範例：

proxy.example:1080
proxy.example:1080:username:password
socks5://username:password@proxy.example:1080
proxy.example/1080/username/password/2026-12-31

URI 的帳密若含 @ : / % 等符號，請做百分比編碼。斜線格式最後的到期時間使用 yyyy-MM-dd，會保存並顯示在清單的「到期時間」欄；沒有日期可省略最後一段或留空。重新匯入同一入口、端口與帳密可更新日期，未提供日期則保留原日期。含斜線的密碼請改用 CSV。CSV 可處理逗號、引號及換行：

host,port,username,password,name,expiresOn
proxy.example,1080,"name,one","p:/@,word","我的線路",2027-01-11

開啟軟體或匯入後自動檢測實際 IP；隨時可按「立即檢測」，有選取時更新選取節點，未選取時更新全部。再次點擊已選取節點可取消該項；點清單空白處、按 Esc 或按底部「清除選取」可取消全部。Ctrl／Shift 可多選，背景更新不會恢復已清除的選取。TCP 經 SOCKS5 連線到 HTTPS 出口查詢服務，UDP 經該代理向 STUN 服務實際收發。僅有 UDP ASSOCIATE 回覆不算通過。檢測耗時是 TCP 協商、TLS 及 HTTP 查詢的總耗時，並不是遊戲 ping。

預設 TCP 檢測目的地為 api.ipify.org，UDP 為 stun.cloudflare.com:3478。只有這些測試請求使用此檢測連線；代理主機及測試 STUN 主機的初始名稱解析使用 Windows DNS。服務失效或網路封鎖也可能令檢測失敗，不能單靠結果判定代理商故障。

節點資訊：實際 IP 與連入 IP 分開顯示

節點清單前三欄依序為「實際 IP」、「連接帳號／連接端口」、「連入 IP」。實際 IP 使用最近一次 TCP 實測結果，尚未檢測則標示「未驗證」；UDP 實際 IP 另列於選取節點後的詳情。連入 IP 為匯入的代理伺服器入口，若匯入網域名稱則保留原主機名稱。無帳號驗證的節點顯示「免帳號／端口」。長帳號省略時，端口仍完整顯示，將滑鼠移至該欄可查看完整帳號；介面不顯示密碼。窗口管理、連線檢測、全局代理選單與分配預覽皆可辨識這三項資訊。

代理與檢測：同一頁管理節點及檢測結果

原本的代理清單與連線檢測已合併為「代理與檢測」。匯入、刪除、匯出、分配與檢測均在同一頁。主表顯示實際 IP、帳號／端口、連入 IP、到期時間、TCP／UDP 狀態、延遲及分配數。選取節點後展開「節點詳情」，可查看 UDP 實際 IP、連線與驗證、檢測時間及完整訊息。搜尋支援名稱、帳號、連入 IP 與實際 IP，不搜尋密碼。檔案匯入、匯出、重測、暫停／恢復與刪除收在「更多」，進階說明與技術紀錄可展開查看。

開啟軟體後會自動檢測清單全部節點，匯入或重新匯入節點也會自動加入背景佇列；不必勾選開關或反覆按檢測。單條失敗繼續其他節點，約 5 分鐘後自動重試；TCP／UDP 通過約 30 分鐘後複測。可暫停後續自動檢測，手動或匯入仍會檢測，但不恢復週期複測；請在「更多」按「恢復自動檢測」。清單會顯示狀態、TCP 實測出口、估計所在地、入口 TCP 連線延遲及已分配數。延遲包含入口 DNS 與 TCP 建立，不是遊戲 Ping；SOCKS、HTTPS TLS 與取得實際 IP 的 TCP 檢測耗時在詳細資料另外列出。選取一條代理可在下方查看 TCP／UDP 兩個出口、連線耗時、UDP 往返、業者與測試時間。超過 30 分鐘的結果標示「待複測」，不會把舊紀錄當成即時狀態。

所在地透過相同代理向 ipwho.is 查詢已測得的 IP，不傳代理帳密。國家／城市是 IP 資料庫估計，不是精確街道地址。查詢失敗或限流不影響 TCP／UDP 檢測結論；成功結果快取一天。

  1. 在代理清單按「分配」，會自動使用清單全部代理，不必逐條選 IP。
  2. 輸入每條代理分配幾個目標，例如清單有兩條代理、每條三個，即可分配六個程序。目前總計上限十個。
  3. 依程序檔名、執行檔路徑或窗口標題篩選，勾選需要的目標。篩選只縮小目前清單，不會自動加入未來新開的程序，也不會清除已勾選項目。
  4. 確認表格中的「將使用代理」。同一條代理可共用多個目標；同一 PID 的多個窗口只分配一次。獨占綁定需連同原目標一起改為共用。
  5. 服務連線時可勾選「分配後立即檢測並啟用」。已存在的遊戲連線要自行重新連線；未啟動雷電仍需到窗口管理按啟用／啟動。
  6. 沒有服務時只儲存離線分配，沒有實際代理或封鎖。安裝服務後在診斷頁移交，再啟用；程序已重開時先重新選取。

預設不含子程序；0.1.9 可明確勾選涵蓋。 共用同一代理會共用出口，畫面會標示共用數，不能宣稱為每窗口獨立 IP。不同代理有相同出口時仍會拒絕獨立分流。

0.1.8：依規則自動分配並開始代理

  1. 在「窗口管理」或「代理清單」按「自動代理」。需要 0.1.8 背景服務。
  2. 選擇目前雷電安裝位置的所有 NAT 實例，或輸入一般程序的完整檔名／完整路徑，支援 .exe 和遊戲的 .bin。例如 game.exe、TWClient.bin，不支援空白或萬用字元。檔名匹配採完全相同、不分大小寫；窗口標題篩選仍只適用手動批次清單。
  3. 設定每個 IP 的目標數（1–10），按「保存規則並開始自動代理」。服務會從代理清單依順序分配，初始保持封鎖，TCP／UDP 實測通過後自動放行。
  4. 服務持續探索新目標，介面關閉後仍生效。每個 IP 已占用的名額會保留，新增目標填入空位；不會因失敗、重排清單或新增 IP 就切換既有綁定。一般程序結束後釋放名額；雷電停止時保留實例綁定。雷電本身需由使用者或「啟用／啟動雷電」啟動。

預設不繼承子程序；未勾選涵蓋時，即使子程序與父程序檔名相同，也只接管可辨識的根程序。同 PID 多個窗口只算一個目標。總管理上限十個；容量不足或已有獨占綁定時，超出的目標維持未分配，不能當成已封鎖或已代理。

「暫停自動代理」停止新增並封鎖原有自動綁定；個別「暫停封鎖」不會被自動規則重新啟用。「解除綁定」恢復原有網路，該目標不會立即被相同規則加入；一般程序重開成新身分後會重新匹配。更換匹配方式會暫停舊自動綁定，請解除不再需要的項目。

探索以約兩秒為一輪，網路檢測會延長該輪時間。完整路徑規則會在核心執行時預先攔截新程序，再辨識及分配；檔名規則在探索前仍可能直連。已有連線需要自行重新連線。服務或驅動尚未就緒、崩潰及不支援路徑不在啟動保護保證內。顯示「代理執行中」代表規則已下達，仍須從目標內驗證出口。

0.1.8 遊戲組：登入器與遊戲共用 IP

在「自動代理」選「遊戲組」，填入登入器與遊戲客戶端兩條完整路徑，保存後再啟動登入器。每次啟動各成一組，同組兩個指定程式共用原 IP；每個 IP 的名額按組計算。登入器退出後遊戲不換 IP，全部成員結束約十秒後釋放名額。一般程序可另選涵蓋子程序；指定遊戲組仍不納入其他映像。

兩條指定路徑在辨識前保持封鎖；遊戲組容量不足、來源無法確認亦封鎖。只支援可驗證父子關係的兩個映像鏈；若登入器過快結束而未被觀察到、或經其他中介程式啟動，請重新從登入器開啟。窗口管理顯示成員數、累積上下載、TCP 連線與 UDP 關聯；關聯數本身不代表 UDP 已成功收發。實際遊戲相容性以測試結果為準。

3. 雷電實例分配

  1. 在「設定」選擇雷電 9 的 ldconsole.exe。本機預設為 C:\LDPlayer\LDPlayer9\ldconsole.exe。
  2. 重新整理窗口；只支援能辨識的單網卡 NAT 設定。使用安裝路徑＋實例編號保存綁定。
  3. 選擇實例 →「分配代理」，設定每個 IP 的目標數；工具依清單順序自動分配並檢測啟用，不需要逐一指定 IP。
  4. 按「啟用／啟動雷電」。服務先建立封鎖與路由規則，再完成代理檢測，最後由目前使用者啟動雷電。
  5. 已開啟的實例會詢問是否重啟。重啟會中斷遊戲；若不重啟，請自行關閉舊連線再重新連線。
  6. 從每個實例內查詢實際 IP，並做實際 UDP／DNS 測試。 管理畫面的「代理實際 IP」是檢測器結果，不能取代這一步。

若不同代理測得相同出口，啟用會拒絕獨立分流；若共用無法區分的程序，也會拒絕分流或保持封鎖。未知的新雷電程序在辨識期間會暫時封鎖；背景服務每兩秒重新辨識已知實例，介面開啟時每二十秒重新探索。

4. 一般程序與窗口

若啟動器結束後另開遊戲客戶端，應匹配真正建立連線的執行檔；部分遊戲使用 .bin 作為程序檔名。這是將遊戲客戶端列為獨立目標，不是繼承啟動器的子程序。以完整路徑規則在啟動前保存設定，再由原啟動器啟動遊戲；Windows UAC 與遊戲帳號登入仍由使用者操作。

「＋ 一般程序」列出程序；「拖曳選窗口」需按住按鈕，拖到遊戲窗口後放開。窗口會轉換成 PID＋程序建立時間。同一程序的多個窗口只能共用規則。手動加入的程序重新啟動後需重新選取；使用「自動代理」的確切檔名或路徑規則，可自動接管新程序。

本版只代理明確勾選的程序，不包含子程序；舊版的子程序繼承設定也會關閉。子程序需個別選取，系統共享網路服務及受保護程序仍需要實機驗證。Windows DNS Client 共用程序的 DNS 不屬於目前一般程序保護保證；本版 DNS 轉送目標是雷電 NAT 自有程序的封包。只有 0.1.9 全局模式涵蓋共用 DNS 服務，仍非 TUN／VPN。

本機控制通訊與雷電辨識

雷電 NAT 使用其 VM 程序建立分流；介面與 VM 的子程序不會被自動繼承。回送位址（127.0.0.0/8 與 ::1）的 TCP／UDP 控制通訊保留在本機，以支援模擬器控制、ADB 與一般程式 IPC；目的埠 53 的 DNS 仍遵守代理／封鎖規則。此例外不放行網際網路 IPv6 流量。一般程序結束後會釋放分配名額，活著但被暫停的程序會保留名額。

5. 暫停、解除綁定與故障

操作行為
暫停封鎖保留綁定並關閉該目標現有轉送連線；受管流量保持封鎖。
解除綁定關閉代理連線並移除規則，恢復原有網路。請先確認遊戲是否仍應保持斷線。
更換代理重新分配，先關閉舊 TCP／UDP 關聯，再啟用新設定；不自動挑選其他 IP。
代理故障轉送失敗沒有直連回退；健康檢查以退避方式重試原代理。恢復後仍須重建遊戲連線。
關閉主視窗縮到系統匣；背景服務獨立執行。
結束介面從系統匣選擇結束，服務繼續；解除安裝或停止服務則會終止代理。

引擎程式碼暫不轉送受管 IPv6；無法分類的封包採保守封鎖。在啟用任一規則時，未知 PID、歧義 UDP 埠、部分 IP 分片或 IPv6 擴充封包可能也影響未選取程式。這是尚待驅動實測改善的預覽版限制，請只在隔離測試環境啟用攔截。

不承諾服務或驅動崩潰時仍零直連。ICMP、橋接、其他模擬器、共享網路代理服務與所有反作弊系統均未驗收。

6. 備份與還原

「更多 → 匯出節點」（不含密碼）產生可搬移的 CSV，保留到期時間，但重新匯入後需補密碼。「設定 → 加密備份」保存完整 DPAPI 加密設定。離線備份需相同 Windows 帳戶及電腦；服務備份需相同電腦，無法用於任意電腦移轉。

類型原始檔案
離線設定%LOCALAPPDATA%\WindowSocks\settings.dpapi
服務設定%PROGRAMDATA%\WindowSocks\settings.dpapi
上一版自動備份相同位置的 settings.dpapi.bak

手動還原：先關閉受管程式，結束 xa sk5 介面；服務設定還需由管理員停止「xa sk5 SOCKS5 背景服務」。保留現有檔案副本，再以對應範圍的備份取代 settings.dpapi，保留原目錄權限與 owner.sid。重新啟動服務及介面後再檢測。加密檔仍應妥善保管，不要公開分享。

7. 常見問題

背景服務未連線

可攜模式預設不安裝服務。完成安裝後重新開啟，或用 Windows「服務」確認 WindowSocks 狀態。安裝使用者以外的帳戶不可控制此服務。

缺少 WinDivert／驅動啟動失敗

僅使用官方 WinDivert 2.2.2 x64 配對檔案 WinDivert.dll 及 WinDivert64.sys。本次環境安全軟體阻擋此檔案，未嘗試繞過。請先查明安全性攔截原因，或改用政策允許驅動測試的隔離電腦。不要為了測試關閉防毒或防火牆。檔案存在不代表驅動成功載入，請以診斷中的核心狀態為準。

TCP 成功、UDP 失敗

可能是代理不支援 UDP、代理 UDP relay 被封鎖、STUN 服務不可達，或網路環境限制。請向代理商確認支援 UDP 的線路；本版不把 TCP 成功當成 UDP 成功。

兩個窗口仍顯示相同 IP

先確認每個實例內的結果，再比較代理檢測結果。不同入口可能共用出口，代理也可能輪換；工具不能把共用出口改成固定獨立 IP。已有連線需要重新建立。

解除安裝

先關閉受管程式，從系統匣結束介面，再到 Windows 已安裝的應用程式選擇「xa sk5 → 解除安裝」。解除安裝會停止並移除服務、專屬防火牆規則及程式，保留加密設定；被鎖定檔案在重開機後移除。
