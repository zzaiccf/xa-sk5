# 0.1.23 驗證範圍

本版本是工程預覽版。以下分開記錄後台驗證與仍待使用者驗收的範圍，不公開使用者的程序識別碼、節點位址、帳密、個人路徑或原始診斷檔案。

## 自動回歸

- 核心測試 326 項，涵蓋設定與身分檢查、節點檢測、規則、程序接續、批次清除／關閉、更新交易與服務狀態恢復。
- 原生測試 156,784 項斷言，使用正式封包判斷程式及官方 WinDivert 解析／校驗函式；測試收發函式為模擬，不載入攔截器。
- 子程序追蹤壓力測試強制清除負向快取，再做 100 次真實父系查詢，避免只測到 inventory 或快取命中路徑。另建立真實子程序驗證無 Job Object 時仍繼承暫停規則，並拒絕過期建立時間。
- 原生回歸包含批次順序、完整性、已知／未知 owner 混合、UDP socket 重用、暫停、政策改變、停止／資源釋放，以及診斷換檔與保留範圍。
- 隔離 WPF 驗證規則添加頁在慢速探索與背景忙碌時可開啟、取消與儲存；驗證清除全部 IP 與關閉程序的確認、取消、重複點擊防護與舊服務能力提示。
- 發布流程驗證全部組件版本、每檔 SHA-256、官方驅動簽章、安裝 EXE 內嵌套件，以及隔離目錄內由舊版更新至本版的檔案交易；使用合成設定資料，不替換正在使用的安裝或啟停真實服務。

## 真實驅動與普通程序

在實際 Windows 主機以 WinDivert 執行服務開／關對照，確實啟用 IncludeChildren，而非僅保留啟動保護或 inventory 規則。每階段 120 次 ICMP 與一般未綁定 TCP 連線均零失敗；服務中 RTT 平均約 7.55 ms、TCP 建立平均約 9.40 ms。此結果是特定主機／時間點的量測，不是所有網路環境的效能保證。

普通測試登入器退出後，子程序三輪 TCP／UDP／DNS 使用指定出口；暫停時 HTTPS 被阻止，恢復後沿用原出口。早期雙節點測試亦驗證兩棵程序樹的不同出口與互不影響；最後一輪僅有一條可用節點，不冒稱完成新的雙出口驗收。

## 遊戲與虛擬機限制

特定遊戲已實際進入空白帳密頁，子程序在同一代理樹內，真正遊戲通道約 49 ms 建立。另觀察到較長的初始化等待，以及未輸入帳密約 180 秒後上游 EOF／連線中斷。

同期主機 88 次 ICMP／TCP 零失敗。對同一目的端，不送遊戲資料的直連與明確 SOCKS 連線都維持 210 秒，沒有 EOF；但其協定狀態與真正遊戲不同，無法據此確認斷線來源或未登入逾時假設。沒有傳送猜測的遊戲封包、心跳或帳密。

登入後遊玩、各遊戲允許的多開方式、雙雷電／雙 VMware 實機、橋接模式及長時間穩定性仍須分別驗收。來源無法確認的程序不應僅依同名檔案推定歸屬；同一 PID 內的多個視窗無法在封包層拆成不同 IP。

服務／驅動異常沒有持久 WFP kill switch 保證，亦未宣稱防洩漏或與所有遊戲保護程式相容。節點檢測出口及後台流量計數不能代替實際窗口內的獨立出口驗證。
