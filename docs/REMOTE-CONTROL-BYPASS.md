# 全局代理：遠端控制直連（0.1.11）

全局代理設定新增「遠端控制程式直連」，初次使用與舊設定缺少此欄位時預設勾選；取消後保存為關閉。需要同步更新背景服務、Core 與 WindowSocksNative.dll。

0.1.14 的背景服務新增 RustDesk 分支 `RDxaomao.exe`、`RDxaomaoHost.exe`、`RDxaomaoControl.exe`，連同既有的 `rustdesk.exe` 一併預設辨識。大小寫不影響，主程式、Host、Control 及無視窗服務程序均依實際執行檔辨識。其他編譯或改名的檔案可在「其他遠端程式」加入完整本機 .exe 路徑。

## 調查與選擇

- [AnyDesk 官方網路說明](https://support.anydesk.com/docs/firewall)：使用 TCP 80、443、6568 等連線，另有 UDP 區網探索。443 也由一般網站使用，不能將整個埠視為遠端流量。
- [Microsoft RDP 說明](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/remotepc/change-listening-port)：預設監聽埠為 3389，使用者可修改登錄中的 PortNumber。因此 RDP 服務端例外須讀取實際監聽埠，並確認 TermService 的程序身分。
- [RustDesk 官方部署說明](https://rustdesk.com/docs/en/self-host/client-deployment/)：Windows 客戶端可作為背景服務執行。全局例外必須涵蓋遠端程式的服務程序，不能只掃描目前登入使用者的可見窗口。
- 本機唯讀程序清單確認有 AnyDesk、Chrome remoting_host、DeskIn 與 RdViewer。沒有更動或重新啟動這些遠端程式。

實作採程序辨識，讓遠端程式的 TCP／UDP 直接沿用原網路，不依目的埠或雲端 IP 全面放行。內建常見遠端程序名稱；可在「其他遠端程式」加入改名版或未內建程式的完整本機 .exe 路徑。自訂例外針對該執行檔的全部連線，不辨識瀏覽器中的個別分頁。

## 規則與限制

優先順序為明確程序／子程序規則、啟動保護、遠端直連、全局代理。明確暫停封鎖、遊戲組或指定代理仍優先，不會被遠端例外解除。遠端例外與區網直連是獨立選項。

- 核心以實際執行路徑的精確檔名或使用者指定完整路徑比對。快取使用 PID＋建立時間及政策代數，不因 PID 重用或移除自訂路徑而沿用舊結果；新開遠端程序在首個可辨識封包即判斷，不等待兩秒服務掃描。
- 原本直接連線的遠端 TCP／UDP 封包直接重注入，啟用全局時不要求這些連線重建。若原本已被代理，改為直連仍需應用程式重建連線。
- 遠端直連在全局檢測失敗的封鎖狀態仍有效，亦涵蓋可辨識的遠端 IPv6 連線；其他外網的 IPv6 保持原封鎖策略。
- RDP 客戶端依執行檔辨識。RDP 服務端只允許核實的 TermService PID＋建立時間＋本機監聽埠，及該監聽埠的 System 程序流量；不放行整個 svchost.exe，也不對所有程式放行 3389／443。
- 系統共用 DNS 仍沿用原有代理政策。自訂或未辨識的程序、無法取得程序身分的流量，沒有自動直連保證。例外不代表軟體簽章或安全性信任驗證。
- 勾選的遠端直連在舊版服務／核心上會於送出啟用命令前明確拒絕，不會靜默忽略選項；取消勾選才可明確使用舊版全局行為。停用全局不受此版本檢查阻擋。

## 驗證

144 項核心測試通過，包含以無視窗 ping 複製檔作為合成遠端程序的實際程序路徑辨識、七種常用程序名、IPv4／IPv6、檢測失敗封鎖狀態、取消勾選、精確自訂路徑、相似檔名不命中、PID 建立時間、快取更新、明確代理／封鎖／啟動保護優先、RDP 自訂埠與不相關服務隔離、原子驗證失敗及 DPAPI 保存。

WPF 實際對話框驗證預設勾選、關閉後保存、自訂路徑保存、正常／最小尺寸以及舊服務能力檢查；既有自動檢測與固定模擬器配置測試通過。

以上隔離測試未載入 WinDivert，也沒有切換使用者正在使用的全局代理或遠端連線；尚未量測真實遠端控制延遲。2026-10-20 經使用者同意後，背景服務與核心已隨 0.1.12 完成備份、更新與重啟；服務回報原生引擎執行中且支援遠端直連，全局保持關閉。實際結果見 [驗證紀錄](VALIDATION.md)。
