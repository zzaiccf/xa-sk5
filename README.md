繁體中文 Windows SOCKS5 多開代理工具，包含 WPF 介面、Windows 背景服務、原生封包引擎、安裝程式和測試。

**這是可執行的工程預覽版。** 已通過普通 Windows 程序的真實 WinDivert TCP／UDP／DNS 轉送測試；雙雷電獨立出口與兩小時驗收仍待完成。發布套件包含已驗證簽章的官方 WinDivert x64 配對檔案。

## 0.1.13：模擬器分配方式可選

「自動代理 → 模擬器 → 分配方式」提供兩種模式：

- **依啟動順序**：選雷電或 MuMu 及管理程式，設定每個 IP 的窗口數。已啟動且可辨識的窗口依虛擬機程序建立時間取得清單前方的空位；窗口編號及讀取清單順序不影響分配。已有分配保留原 IP，關閉後釋放名額，重開重新排入；一個 IP 可供 1–10 個窗口共用，總計仍最多十個。容量不足的匹配窗口保持封鎖，明確解除綁定則恢復原網路。
- **固定窗口編號**：使用原有表格逐條指定，未啟動的窗口也保留 IP，重開沿用同一對應；可讓不同窗口共用同一節點。

依啟動順序需要 0.1.13 背景服務，舊服務或離線時先保存草稿。雷電由服務辨識實例；MuMu 首次辨識新窗口須保持介面開啟或按「讀取窗口」，後續以已核實的 NAT 程序身分辨識。兩種模式沿用代理檢測與封鎖政策，橋接模式及 MuMu 實際轉送仍需逐機驗收。更新不會自行切換現有規則。

## 0.1.12：手動立即檢測與低頻自動複測

「代理與檢測」新增「立即檢測」：有選取時更新選取節點，未選取時更新全部；該頁右上角的重新整理也會啟動新檢測。手動操作可立即更新尚未過期的結果，重複點擊不會重複排入相同節點。

開啟軟體與匯入仍先檢測一次；成功後每 30 分鐘複測，失敗後 5 分鐘重試。暫停自動檢測後仍可手動檢測或匯入，週期複測須在「更多」按「恢復自動檢測」才恢復。背景服務的使用中節點健康檢查也改為相同頻率，需要 0.1.12 服務。健康有效期為 37 分鐘，涵蓋排程與一次失敗後重試；首次未成功或連續兩次失敗仍封鎖，不會改為直連。

## 0.1.11：全局代理保留遠端直連

按「全局代理」可見預設勾選的「遠端控制程式直連」。AnyDesk、Chrome 遠端、DeskIn、RdViewer、TeamViewer、RustDesk、RDP 等程序可直接連線；其他遠端程式可加入完整 .exe 路徑。依程序精確辨識，不放行整個 443 或 3389 埠；指定代理與暫停封鎖仍優先。設定需搭配 0.1.11 背景服務與原生核心，舊元件不會靜默忽略勾選。研究來源、規則、DNS 限制與測試範圍見 [遠端直連說明](docs/REMOTE-CONTROL-BYPASS.md)。

## 0.1.9：全局代理與程序樹

- **全局代理**：「窗口管理 → 全局代理…」選擇一條 SOCKS5 節點。代理本機所有可歸屬程序的 IPv4 TCP／UDP，包含 Windows 共用 DNS 與背景服務；不限十個程序。原有指定程序、遊戲組、啟動保護與暫停封鎖規則優先。可按「停用全局」恢復原規則。
- **區網直連**預設開啟，保留 IPv4 私有位址、link-local、多播與廣播；127.0.0.0/8、::1 本機控制／ADB 通訊保留直連。目的埠 53 的 DNS 仍走 SOCKS 並轉送至 1.1.1.1。外部 IPv6 不轉送。
- **涵蓋子程序**：手動分配或一般程序自動規則可明確勾選。適用遊戲登入器、中介程式及由主機程序連網的模擬器；需選實際網路程序或可驗證的祖先。已觀察的子程序在根程序結束及服務重啟後保留代理，最後一個成員結束才釋放名額。每棵樹上限 512 個子程序；預設仍只代理選取的程序，雷電與指定遊戲組的成員規則不變。
- 全局節點啟用前解析為 IPv4 並保存，避免 SOCKS 上游 DNS 形成循環；上游位址改變時請重新套用全局設定。全局模式的 STUN 健康檢測使用 SOCKS UDP 網域名稱封裝，由代理解析，不依賴已被封鎖的系統 DNS。上游與健康檢測由服務程序直連建立 SOCKS；首次檢測未通過維持封鎖，只有先前實測成功的連線才有一次失敗的寬限。

這些功能擴大可代理的程序範圍，尚未完成各廠牌模擬器／遊戲實測。橋接、Hyper-V／WSL 的轉送流量、ICMP、無法歸屬的封包與所有反作弊遊戲不在相容承諾內。服務／驅動停止或崩潰不保證阻止直連。詳見 [操作說明](docs/操作說明.html) 與 [驗證紀錄](docs/VALIDATION.md)。

## 代理清單檢測與共用分配

介面採淺色工作區與統一的按鈕、選單、表格和對話框。常用操作直接顯示，進階操作放入「更多」，說明與技術資訊改用提示或折疊區。設定頁集中管理服務、模擬器路徑與資料工具。

「代理與檢測」合併原本的代理清單與連線檢測頁。點「匯入節點」貼上資料，「分配」設定窗口；檔案匯入、匯出、重測、暫停／恢復自動檢測與刪除在「更多」。搜尋可篩選連入 IP、實際 IP、帳號及名稱，不搜尋密碼。

再次點擊已選取的節點即可取消該項；點清單空白處、按 Esc 或按清單底部的「清除選取」可取消全部選取。Ctrl／Shift 多選維持原操作，清除後「立即檢測」會更新全部節點，背景更新不會恢復已取消的選取。

主表保留實際 IP、帳號／端口、連入 IP、到期時間、TCP／UDP 狀態、延遲與分配數。選取節點後展開「節點詳情」，可查看 UDP 實際 IP、驗證、測試時間、所在地及完整訊息；未提供的到期日期仍留空。可用數僅計入最近 30 分鐘的通過結果。

0.1.10 的「窗口管理」新增連入時長，以背景服務的本次代理啟用時間計算，每秒更新；暫停、封鎖、換 IP、重開窗口或重啟服務後重新計時，TCP／UDP 連線數可懸停時長查看。這是代理規則生效時長，不是遊戲登入時長。

「自動代理 → 模擬器」可選雷電或「其他模擬器 · MuMu」。選擇管理程式後讀取窗口，或加入原始編號，再逐條指定節點；「依編號配置」按模擬器、安裝位置及編號排序快速填入，也可手動讓多個窗口共用一條 IP。固定設定以安裝位置＋實例編號儲存，包含尚未啟動的窗口，沒有按開啟順序補位；不同模擬器的 #1 是不同目標，總管理上限仍為十個。自動填入數量只影響快速配置，不限制手動共用數。

固定窗口及服務端計時需要 0.1.10 背景服務；舊服務或離線時可先儲存草稿，更新後須再次按「儲存配置」套用。MuMu 使用 [官方 MuMuManager 命令介面](https://mumu.163.com/help/20240726/35047_1170006.html) 的實例編號及 `headless_pid`，不將外殼 PID 當成 NAT 網路程序。首次啟動 MuMu 窗口時請保持介面開啟以讀取清單；服務之後以經核實的程序路徑與命令雜湊辨識重開，無法唯一辨識時等待重新讀取，不猜測窗口順序。僅適用可辨識的 NAT 模式；MuMu 尚未完成本機實機轉送驗收。

- 節點清單依序顯示「實際 IP」、「連接帳號／連接端口」、「連入 IP」。實際 IP 為最近一次 TCP 實測結果，未檢測標示「未驗證」；入口依匯入的 IP／主機名稱顯示。免驗證節點標示「免帳號」，長帳號可懸停查看完整內容，端口保留顯示。窗口管理、連線檢測、全局選單與分配預覽使用同樣的節點資訊，不顯示密碼。
- 斜線格式最後的 `yyyy-MM-dd` 日期會保存並顯示在「到期時間」，例如 `proxy.example/1080/user/password/2027-01-11`；省略日期或留空時，新節點該欄為空。同一入口、端口、帳密重新匯入可更新到期時間，未填日期則保留已知日期。CSV 第六欄 `expiresOn`、匯出、加密備份與離線移交也保留日期。日期是來源資料，不代替連線實測。
- 開啟軟體即自動檢測清單全部節點；匯入或重新匯入節點也會自動加入檢測佇列。背景逐個更新實際 IP，檢測期間仍可匯入與操作介面，單條失敗不影響後續節點。失敗約 5 分鐘後重試，TCP／UDP 通過約 30 分鐘後複測。「立即檢測」可隨時更新選取節點，未選取則更新全部，重複點擊會合併相同工作。暫停自動後，手動及匯入仍可檢測，但不會恢復週期排程；請在「更多」明確恢復。清單顯示狀態、實測出口、估計所在地、TCP 測試延遲與分配數，選取後查看連線／UDP 往返時間、業者及檢測時間。
- 在代理清單按「依數量分配給窗口」→ 設定每條分配 1–10 個目標 → 用程序檔名、完整路徑或窗口標題篩選 → 勾選並檢查對應預覽 → 確認分配。工具自動使用清單內全部 IP，總計以 10 個目標為上限。
- 相同代理可明確共用；獨占綁定必須一起選入共用分配才會轉換。相同 PID 的多個窗口不能重複綁定。服務再次驗證 PID＋建立時間；持續匹配新程序請使用「自動分配並代理」。
- 一般程序預設不繼承子程序，可明確勾選涵蓋；遊戲組只納入指定完整路徑且可證明父子關係的登入器與遊戲，其他子程序不代理。
- 沒有服務時可先儲存離線分配，畫面標示「待服務套用 · 未代理」；安裝後使用診斷頁的移交功能，再啟用。程序若已重開，須重新選取。
- 所在地透過同一代理，向 [ipwho.is](https://ipwhois.io/documentation) 查詢已測得的 TCP 實際 IP；不傳帳密。結果僅為資料庫估計，成功快取 24 小時、失敗快取 5 分鐘，查詢失敗不改變 TCP／UDP 檢測結果。延遲不是遊戲 Ping。

## 開啟與安裝

0.1.8 增加連線事件診斷：自動記錄每條受管連線的目的端、SOCKS 建立、雙向 byte 數、應用端／上游 EOF、Winsock 錯誤及規則中斷；不記錄帳密與封包內容。修正半關閉連線仍顯示活動、以及程序 socket 消失後殘留代理連線的清理。最近事件可在「診斷與設定」查看並匯出 JSON，背景服務也寫入受 ACL 保護的 ProgramData/WindowSocks/network-events.jsonl（約 2 MB 輪替，保留上一份）。

診斷會附上遊戲程序身分與窗口資訊，以及驅動版本、SHA-256、簽章和載入狀態。此模式仍使用 WinDivert，無法保證不被遊戲辨識；Socket 錯誤或 EOF 不能單獨證明反作弊攔截。遊戲原生代理或外部網關屬於另一種架構，尚未實作多開分流。遊戲畫面擷取在本次由 Codex 電腦操作測試完成，應用程式本身不會在背景連續截圖。

0.1.8 新增「遊戲組」：在自動分配選擇遊戲組，上方填登入器完整路徑，下方填遊戲客戶端完整路徑，先保存再啟動登入器。每次啟動各成一組；同組 Login.exe 與 TWClient.bin 共用代理，各組依每 IP 名額分配。登入器結束後仍保留遊戲原 IP，整組結束約十秒後釋放名額。窗口管理顯示成員數、累積流量與核心已建立的 TCP 連線／UDP 關聯數。

遊戲組的兩條路徑先封鎖，再辨識及分配；容量不足或來源不明時保持封鎖。約每 250 ms 獨立探索，不受代理檢測等待影響。只支援兩個指定映像直接形成的父子鏈；若登入器過快結束而未被觀察到，或由未指定的中介程式／服務啟動遊戲，會顯示來源未確認，請重新啟動登入器。服務重開保留已記錄的 PID＋建立時間及組別。這不代表所有遊戲的啟動鏈都已相容。

**0.1.1 已加入：主程式「診斷與設定 → 安裝／修復代理元件」。** 按下後由 Windows 顯示 UAC，使用者親自同意；維護程式自動檢查套件、下載固定官方 WinDivert 2.2.2、檢查 SYS 簽章、安裝服務並以 `false` 篩選器測試驅動載入。可攜版可直接安裝到 Program Files，不必手動複製驅動。遇到安全性攔截會停止並顯示原因，不調整防毒、UAC 或驅動簽章政策。實際 UAC／驅動測試尚未在此開發程序中執行。

- `artifacts/local/xa sk5.exe`：固定的本機測試入口；已內含 .NET 執行階段，直接執行即可。
- `artifacts/release/0.1.15/xa-sk5-Setup-0.1.15.exe`：安裝介面、背景服務、開始功能表捷徑及解除安裝項目；由 Windows 要求管理員權限。
- `artifacts/release/0.1.15/xa-sk5-0.1.15-win-x64.zip`：完整可攜資料夾；請解壓縮全部檔案後執行。
- `docs/操作說明.html`：繁體中文操作、備份還原、診斷與限制。
- `docs/VALIDATION.md`：已執行與未執行的測試；代理檢測與實例出口驗收分開記錄。

沒有 WinDivert 時，可匯入、檢測、匯出及加密備份代理；啟用實例會明確拒絕。安裝包與程式目前沒有商業程式碼簽章。

## 建置

需求：Windows x64、.NET 10 SDK、Visual Studio C++ x64 工具及 Windows SDK、PowerShell 7。

```powershell
./scripts/Build.ps1
```

本機開發預設只更新 `artifacts/local` 可執行目錄，不產生 ZIP 或安裝包。每次測試執行其中的 `xa sk5.exe`；重新建置前先結束該測試介面，避免檔案被使用。只有明確要求「發布」時才執行以下命令，產生可攜 ZIP：

```powershell
./scripts/Build.ps1 -Package
# 已完成本機建置時可直接打包，無須重編譯：
./scripts/Package.ps1 -PortableOnly
```

## 0.1.8 自動分配

代理池使用清單全部 IP，指定每 IP 的目標數即可自動分配，無須逐一選 IP。背景服務可保存雷電 NAT 全實例或一般程序完整檔名／路徑匹配，持續探索新增目標。TCP／UDP 通過後放行；同名子程序不繼承，既有綁定不因故障換 IP。容量不足顯示未分配。一般程序探索前可能已產生直連，需重新連線；不宣稱從第一個封包起零直連。

Tools 新增 `migrate-local`（既有 DPAPI 代理移交服務）及 `probe-service`（透過服務測試，不啟動驅動）；不輸出密碼。
